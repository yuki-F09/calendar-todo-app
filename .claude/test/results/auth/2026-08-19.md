## 新規登録（`/auth/signup`）

### TC-006: 正しい情報で新規登録できる
- **結果**: PASS
- **確認内容**: 未登録アドレス（tc006test20260819@example.com）でパスワード一致で送信 → 「確認メールを送信しました。メールをご確認ください。」が表示され、ページ遷移なし

### TC-007: パスワードと確認用パスワードが一致しない場合エラーが表示される
- **結果**: PASS
- **確認内容**: 異なるパスワードを入力して送信 → 「パスワードが一致しません。」エラーが即座に表示（APIリクエストなし）

### TC-008: 既登録のメールアドレスで登録しようとするとエラーが表示される
- **結果**: FAIL
- **確認内容**: user@nextapp.com（登録済み）で送信したが、エラーではなく「確認メールを送信しました。メールをご確認ください。」が表示された
- **原因**: Supabaseが既登録メールアドレスに対してもエラーを返さず成功レスポンスを返している（Supabase の `signUp` はセキュリティ上の理由でメール重複をエラーにしない設定になっている可能性あり）
- **対応案**: Supabase ダッシュボードの Auth 設定を確認し、重複登録時のエラーハンドリングを実装する

### TC-009: 送信中はボタンが無効化される
- **結果**: PASS
- **確認内容**: TC-008実行中、APIリクエスト中にボタンラベルが「通信中」に変わり、`disabled` 属性が付与されることを確認

### TC-010: ログインページへのリンクが機能する
- **結果**: PASS
- **確認内容**: signup ページの「ログイン」リンクをクリック → `/auth/login` へ遷移

## ログアウト

### TC-011: ログアウトすると `/auth/login` へリダイレクトされる
- **結果**: PASS
- **確認内容**: `/` のログアウトボタンをクリック → `/auth/login` へリダイレクトされた

### TC-012: ログアウト後に `/` へアクセスすると `/auth/login` へリダイレクトされる
- **結果**: FAIL
- **確認内容**: ログアウト後に `/` へナビゲートしたところ、`/auth/login` へリダイレクトされずカレンダーページ（認証済みレイアウト）がレンダリングされた
- **スクリーンショット**: screenshots/error-TC-012-20260819-1147.png
- **原因**: ミドルウェアがログアウト直後の `/` アクセス時にセッションを正しく無効と判定できていない可能性。Supabase の refresh token が残存しており、ミドルウェアが自動的にセッションを再取得していると考えられる
- **コンソールエラー**: なし
- **APIエラー**: なし
- **対応案**: `lib/supabase/proxy.ts` のセッション管理・ミドルウェアのセッション検証ロジックを確認する
